# Native Golsta Collector Integration

This integration keeps Golsta's client source and compiled artifact unchanged
while moving the collector into the C2R2 server process. C2R2 consumes the
compiled PE, implements the documented GLST transport, and exposes the stored
archives through its authenticated API.

## Data Flow

1. The operator runs `/harvest` for a selected Windows agent.
2. C2R2 reads `c2r2-server/modules/golsta.exe` and uploads it over the existing
   TLS agent session.
3. The agent runs the PE once, waits for completion, and removes the temporary
   executable.
4. Golsta sends its result to C2R2's native TLS collector.
5. C2R2 decrypts and validates the archive, writes it atomically, and prints
   the new result metadata in the interactive CLI.
6. C2R2 exposes status, metadata, and archive downloads through the
   existing authenticated C2 API.

The native collector defaults to `0.0.0.0:9090`, while the operator API remains
on the configured C2R2 API port (`5555` by default).

## Private Boundary

- Golsta remains in its private repository and is not modified by C2R2.
- Only the compiled `c2r2-server/modules/golsta.exe` is consumed by C2R2.
- `modules/`, conference artifacts, local control files, and harvested archives
  must remain ignored by Git.
- C2R2 receives the encrypted packet, validates ZIP entry paths, and streams
  the stored archive without extracting it to the filesystem.

## Configuration

The native receiver needs the same hexadecimal shared secret used when the
unchanged Golsta client was built. The default matches the supplied client
artifact; use a different value only when the client was built with another
secret.

```powershell
# Native collector is started by C2R2 itself
.\c2r2-server.exe --golsta-bind 0.0.0.0 --golsta-port 9090 --golsta-loot .\golsta-loot
```

The collector uses the same TLS certificate files as the C2R2 agent listener.
The Golsta client intentionally does not require certificate-chain validation;
the packet HMAC and AES-GCM authentication remain mandatory.

## C2R2 API Contract

All routes require the normal C2R2 session bearer token:

| Method | Route | Result |
|--------|-------|--------|
| `POST` | `/api/agents/:id/harvest` | Upload and execute the compiled Golsta PE |
| `GET` | `/api/golsta/status` | Native collector health and harvest count |
| `GET` | `/api/golsta/harvests` | Result metadata without archive contents |
| `GET` | `/api/golsta/harvests/:id/archive` | Stream one ZIP archive |

Archive identifiers are generated by C2R2 and reject path separators and
traversal sequences. Archive responses use `Cache-Control: private, no-store`
and `X-Content-Type-Options: nosniff`.

Expected error behavior:

| Status | Meaning |
|--------|---------|
| `401 Unauthorized` | Missing or invalid C2R2 session token |
| `503 Service Unavailable` | Native collector is not configured |
| `404 Not Found` | Archive identifier is unknown |
| `502 Bad Gateway` | Local archive storage failed |

## Validation

The collector has focused tests for secret parsing, packet decryption, unsafe
archive paths, and the live watcher. The complete release check is:

```bash
cargo test --release -p c2r2-server
cargo build --release -p c2r2-server --target x86_64-pc-windows-gnu
```

The lab end-to-end check must verify that a new result appears after
`/harvest`, that the archive downloaded through C2R2 matches the file under
`--golsta-loot`, and that the temporary agent executable is removed.

## Rollback

1. Stop C2R2.
2. Move the `--golsta-loot` directory to a protected backup if the archives
   must be retained.
3. Remove `c2r2-server/modules/golsta.exe` to disable `/harvest` dispatch.

This integration does not add persistence or change the agent's persistence
configuration.
